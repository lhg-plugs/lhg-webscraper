# lhg-scraper-anti：反爬应对清单

> **合规声明**：本 skill 只收录**合规**的反爬应对手段。任何涉及绕过登录、绕过验证码、对抗站点风控的"技巧"都不在收录范围——遇到站点明确拒绝自动化访问，正确动作是停手，不是升级对抗。

目标：把"被站点拦了怎么办"变成一张清单：先判断拦的性质，再选合规手段，手段用尽还不行就认栽——认栽也是方案的一部分。

## 1. 何时使用

- 采集方案卡里要填"反爬应对"一节 → 用第 3 节清单逐条勾选
- 采集中途被限流/弹验证 → 先跑第 2 节"先判断再动手"，再选手段
- 用户要求"想办法绕过" → 不用本 skill，直接走 `lhg-scraper-compliance` 第 6 节拒绝

## 2. 输入与输出

**输入**：站点类型（静态/渲染/API）、已观察到的反爬信号（限流/验证/封禁）、合规预检结论（必须是通过）。

**输出**："反爬应对清单"（每条含：手段 / 参数 / 为什么合规 / 不做清单对照）。

## 3. 分步方法论

### 第一步：先判断拦的性质（动手前必做）

| 信号 | 性质 | 动作 |
|---|---|---|
| 偶发 429 / 响应变慢 | 站点在提示"你太快了" | 降频 + 退避，这是善意的提醒 |
| 固定验证码 / 人机验证 | 站点在说"请勿打扰" | 停手，不绕过 |
| IP 被封 / 账号被锁 | 站点在说"请离开" | 停手，不换身份绕过 |
| robots.txt 新增 Disallow | 规则变了 | 重新做合规预检，按新规则来 |

**核心判断**：站点给你"减速带"（429/变慢）→ 你减速；站点给你"墙"（验证/封禁/Disallow）→ 你停。把减速带当成墙去翻，是对抗；把墙当成减速带去闯，也是对抗。

### 第二步：合规手段清单（按推荐顺序）

1. **如实 UA**：带上说明用途与联系方式的 User-Agent。很多站点的第一道风控只是"不认识你"，自报家门就能过。
2. **降频限流**：间隔提到 2–5 秒，并发降到 1。被 429 后按指数退避（1s → 2s → 4s → 8s），最多重试 3 次。
3. **错峰采集**：把任务放到站点低峰期（如凌晨），总量不变，对站点影响最小。
4. **减量采集**：只取必需字段、只做增量、用 sitemap 拿 URL 清单代替全站爬。请求数降一个数量级，很多"反爬"自然消失。
5. **渲染型站点用无头浏览器**：页面必须 JS 渲染时，用无头浏览器正常加载（带合理等待），而不是去逆向加密参数。**逆向站点的前端加密/签名算法属于对抗手段，不做**。
6. **走官方 API**：站点有开放 API（哪怕要申请 key）→ 优先用 API。这是站点希望你用的方式。

每条手段配一句话"为什么合规"：因为它没有欺骗站点、没有隐藏身份、没有超出站点公示规则允许的范围。

### 第三步：不做清单（写进方案卡，向用户明示）

- ❌ 绕过登录（借用/盗用他人 Cookie、模拟登录）
- ❌ 绕过验证码（打码平台、模型识别、对接验证接口）
- ❌ 绕过付费墙（解析会员接口、拼 URL 越权访问）
- ❌ 攻击式并发（代理池 + 高并发打爆站点）
- ❌ 伪造身份（UA 伪装成搜索引擎爬虫蹭白名单）
- ❌ 逆向站点的风控签名/加密参数

**为什么连"伪装成搜索引擎爬虫"都不行**：搜索引擎白名单是站点给守规矩的爬虫的优待，冒充身份去蹭是欺骗。身份可以如实，不能冒充。

### 第四步：手段用尽还不行 → 认栽方案

1. 降频到"一分钟一次"还是被拦 → 说明站点不欢迎，停手。
2. 输出"采集不可行报告"：试过的合规手段、站点的拒绝信号、建议的合法替代（官方 API / 联系授权 / 换数据源）。
3. **不许出现**"要不我们试试 XX 绕过"——清单外的手段不在本插件能力范围。

## 4. 反模式

- ❌ "429 了，加代理继续冲"——429 是让你慢，不是让你换马甲
- ❌ "验证码偶尔才弹，找个打码平台自动过"——偶尔也不行
- ❌ "逆向一下它的签名算法，反正前端代码都看得到"——看得到 ≠ 可以用
- ❌ 把"不做清单"里的手段换个名字再上（如把打码平台叫"智能验证助手"）——换名字还是绕过
- ❌ "先按合规的写，绕过的部分用户自己加"——不提供半成品绕过方案

## 5. 自检与反馈

**质检门**（反爬应对清单发布前逐项打勾）：

- [ ] 清单里每条手段都写了"为什么合规"一句话
- [ ] "不做清单"六条原样列出，无删减、无改名
- [ ] 参数保守：间隔 ≥1 秒、并发 ≤3、重试 ≤3 次（或有 robots 依据）
- [ ] 认栽方案已写：手段用尽后的停手条件与不可行报告模板
- [ ] 无"逆向签名/加密参数""伪装 UA"等对抗表述（用审计脚本 WS-CMP-002 自查）

**标准冒烟用例**：给"偶发 429 的公开 API"出清单 → 应选降频+退避+错峰；给"弹验证码的票务站"出清单 → 不应出任何手段，应转拒绝流程。

**一键提 issue**：发现流程缺口或误判，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-webscraper/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

## 6. 手段参数速查表

| 场景 | 间隔 | 并发 | 重试 | 备注 |
|---|---|---|---|---|
| 默认（无反爬信号） | ≥1 秒 | ≤3 | 指数退避 ≤3 次 | 基准线 |
| 偶发 429 | 2–5 秒 | 1 | 退避 1s→2s→4s | 先降频再观察 |
| robots 有 Crawl-delay: 5 | ≥5 秒 | 1 | 同上 | robots 优先于默认 |
| 渲染站（无头浏览器） | ≥3 秒 | 1 | ≤2 次 | 渲染成本高，更要省 |
| 夜间错峰 | ≥1 秒 | ≤3 | 同上 | 总量不变，换时间 |

**参数调整铁律**：只许往保守调（更慢、更少），不许往激进调。用户说"快一点"时，把这张表给他看——快的前提是站点允许。

## 7. 采集不可行报告模板

```markdown
## 采集不可行报告：<目标站>（日期）
### 已尝试的合规手段
- 如实 UA / 间隔提到 5 秒 / 并发降到 1 / 错峰凌晨执行
### 站点的拒绝信号
- <如：固定验证码 / IP 封禁 / robots 新增 Disallow>（附截图或日志行）
### 结论
- 本次采集不可行，任务终止。
### 合法替代建议
- 官方 API：<有/无，申请地址>
- 联系站点授权：<联系方式页>
- 替代数据源：<公开可采集的同类站点>
```

这份报告是交付物，不是失败证明——它证明了你试过所有合规手段，并且懂得停手。

### 渲染站特别说明

- 无头浏览器按"正常用户"节奏加载：等网络空闲再解析，别用"禁用图片/CSS 求快"之外的加速 hack。
- 滚动加载用"滚到底 → 等新内容 → 数数量没变就停"，加最多 50 次滚动兜底。
- 页面调的 JSON API 如果无需鉴权且返回公开数据 → 直接调 API，比渲染更快更稳。
- **API 需要登录态才能调 → 回到合规拒绝流程**，不许把登录态塞进无头浏览器"顺手"用。

### 何时升级到人工介入

出现以下信号，不要自己"再试一次"，直接把情况同步给用户等决策：

- 站点返回明确的法律警告文本（如"unauthorized access prohibited"）
- 连续三次降频后仍被封禁（说明不是频率问题，是身份问题）
- 目标站 ToS 在任务执行期间更新并新增禁止条款
- 采集到的数据里混入了未预期的个人信息字段

同步模板："<站点>出现<信号>，已暂停采集。合规手段已用尽，建议<停手/申请授权/换数据源>，请决策。"

### 一句话总结

反爬应对的本质是"礼貌"：站点让你慢你就慢，站点让你停你就停。所有"让站点认不出你"的技巧，无论包装得多好，都是对抗——而对抗不在本插件的能力范围里。
