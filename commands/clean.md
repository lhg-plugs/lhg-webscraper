# /lhg-webscraper:clean —— 数据清洗

用户输入在 `$ARGUMENTS` 中：`<原始数据文件>`，`--格式` 缺省按文件后缀判断。

## 合规声明

> **合规声明**：清洗环节会对全字段再做一次敏感信息扫描（身份证号、手机号、密码、住址等）。命中敏感字段的数据列将被剔除并告警，不会"清洗掉痕迹继续用"——不该采的数据，洗干净了也不该留。

## 流程（加载 lhg-scraper-clean 全程指导）

### 1. 摸底

先回答四个问题再动手：数据量多大？字段有哪些？主键/去重键是什么？下游要什么格式？

### 2. 跑清洗四件套

1. **去重**：按去重键去重，报告重复率
2. **去噪**：HTML 标签残留、`&nbsp;`、多余空白、"加载中"占位文本
3. **归一化**：日期统一 ISO 格式、数字去千分位转数值、枚举值映射（如"是/否"→true/false）
4. **空值策略**：关键字段空值整行丢弃并计数；非关键字段填默认值并在报告注明

### 3. 敏感字段二次扫描（硬性）

```
python3 <插件目录>/scripts/audit/webscraper_audit.py --scan-fields <清洗后文件> --format text
```

命中 `WS-SEC-001`（身份证/手机号/密码类字段或值）→ 该列整体剔除，报告中写清"因合规原因剔除 × 列"，不许只删值保留列名"以后再说"。

### 4. 输出清洗报告

```markdown
## 清洗报告
- 输入 n 行 → 输出 m 行（去重 x、丢弃 y）
- 归一化：日期 n 处、数字 n 处
- 敏感扫描：命中 0 / 剔除 × 列（列名）
- 交付：<文件路径>（格式、编码 UTF-8、字段说明见附）
```

## 硬规则

- 清洗不许"创造"数据：空值不许用编造的值填充（如随机生成手机号），只能丢弃或标缺失。
- 敏感列剔除后不许在报告里贴出原始样本——样本本身也是敏感数据。
