# /lhg-webscraper:scrape —— 爬虫采集全流程

用户输入在 `$ARGUMENTS` 中：`<目标站点URL> <采集需求>`，可选 `--增量`（只取新增）、`--渲染`（页面需 JS 渲染）。

## 合规声明（本次输出必须以此开头，不可跳过）

> **合规声明**：本插件只采集**公开可访问**的数据；遵守目标站点的 robots.txt 与服务条款（ToS）；**不**绕过登录、付费墙、验证码（CAPTCHA）；采集频率限流，不给目标站造成负担；使用者自行承担法律责任。任一环节触碰红线，插件将**直接拒绝并说明原因**，不提供变通方案。

## 流程（全程按 skill 方法论执行）

### 第 0 步：合规预检（硬性，不可跳过）

加载 `lhg-scraper-compliance` 第 2 节，先回答五个问题，**任一答案为"是"即拒绝**：

1. 数据是否需要登录后才能看到？→ 是，拒绝
2. 是否涉及付费墙/会员专区内容？→ 是，拒绝
3. 是否需要绕过验证码/人机验证？→ 是，拒绝
4. 目标站 ToS 是否明确禁止爬取？→ 是，拒绝
5. 采集字段是否含个人敏感信息（身份证号、手机号、密码等）？→ 是，拒绝并提示删字段

同时运行合规预检脚本确认 robots.txt 允许：

```
python3 <插件目录>/scripts/audit/webscraper_audit.py --check-robots <目标域名> --format text
```

预检结论写进本次输出的"合规确认"区：**通过（robots 允许 / 无红线）** 或 **拒绝（原因）**。

### 第 1 步：方案设计（加载 lhg-scraper-plan）

输出一张"采集方案卡"：

| 项 | 内容 |
|---|---|
| 目标站点 | URL + 站点类型（静态/渲染/API） |
| 数据清单 | 字段名 × 类型 × 是否必需 |
| 请求策略 | 请求库选型、UA、限流间隔、并发上限、超时 |
| 解析策略 | CSS/XPath/JSON 路径，翻页方式（页码/游标/滚动） |
| 增量策略 | 去重键、断点续传、水位线字段 |
| 交付物 | CSV/JSON/SQLite + 字段说明 |

### 第 2 步：反爬应对清单（加载 lhg-scraper-anti）

- 只列**合规**手段：UA 轮换、限流、重试退避、渲染型站点用无头浏览器；
- 明确写出**不做**的清单（登录态复用、验证码绕过、代理池攻击式并发）；
- 每条应对写清"为什么合规"一句话。

### 第 3 步：数据清洗（加载 lhg-scraper-clean）

- 去重、去 HTML 残留、日期/数字归一化、空值策略；
- 敏感字段二次扫描：即使方案阶段没发现，清洗时再扫一遍，命中即剔除并告警。

### 第 4 步：交付

输出顺序：**合规确认 → 采集方案卡 → 反爬应对清单 → 清洗规则 → 采集脚本**。
采集脚本跑完后附"采集报告"：请求数、成功率、耗时、平均间隔（证明限流生效）。

## 硬规则

- 跳过第 0 步直接给方案 → 不许。
- 用户要求"想办法绕过登录/验证码" → 拒绝，不提供任何变通（hook 也会告警）。
- 采集频率：默认请求间隔 ≥1 秒，并发 ≤3；站点 robots 有 Crawl-delay 的按更大的来。
